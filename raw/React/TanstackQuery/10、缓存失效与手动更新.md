# 缓存失效与手动更新

> **版本基线**：`@tanstack/react-query` **v5.104.x**。
> 官方文档：<https://tanstack.com/query/v5/docs/framework/react/guides/query-invalidation> · <https://tanstack.com/query/v5/docs/framework/react/guides/updates-from-mutation-responses>

## 一、失效（Invalidation）：让缓存过期

`invalidateQueries` 把匹配的查询**标记为过期**，并**可选地立即重新请求**（默认重拉）。

```ts
// 使 ['todos'] 及其子 key 全部失效并重拉
queryClient.invalidateQueries({ queryKey: ['todos'] })
```

> **前缀匹配**：`['todos']` 会命中 `['todos']`、`['todos', 5]`、`['todos', { status:'done' }]` 等一切以 `['todos']` 开头的 key。

### 精确匹配 vs 前缀匹配

| filters 写法 | 匹配范围 |
|---|---|
| `{ queryKey: ['todos'] }` | 以 `['todos']` 为前缀（默认，含子级） |
| `{ queryKey: ['todos'], exact: true }` | **只**精确匹配 `['todos']` |
| `{ queryKey: ['todos', 5], exact: true }` | 精确匹配某个条目 |

```ts
// 只让全部待办失效，不动单条
queryClient.invalidateQueries({ queryKey: ['todos'], exact: true })
```

### 只标过期、不立刻重拉

```ts
// refetchType: 'none' → 只标记 stale，不主动重拉
queryClient.invalidateQueries({ queryKey: ['todos'], refetchType: 'none' })

// 其他取值：'active'（只重拉活跃）/ 'inactive' / 'all'（默认）
```

## 二、手动更新缓存：setQueryData

**不想重新请求、直接用本地已知数据覆盖缓存**：

```ts
queryClient.setQueryData(['todos'], (old: Todo[] | undefined) =>
  old ? [...old, newTodo] : [newTodo],
)
```

- updater 可以是**值**或**函数** `(oldData) => newData`（函数能拿到旧值做增量）。
- 同步生效，所有订阅该 key 的组件立即重渲染。

## 三、从 mutation 响应更新（推荐 vs 失效）

mutation 成功拿到**服务端返回的新数据**时，有两条路：

| 方式 | 优点 | 缺点 |
|---|---|---|
| **`onSuccess` 直接 setQueryData** | 无需二次请求，最省带宽 | 依赖响应数据完整、可信 |
| **`onSettled` invalidateQueries** | 以服务器为准，最可靠 | 会多发一次请求 |

```ts
const mutation = useMutation({
  mutationFn: updateTodo,
  // 方式 A：直接写缓存
  onSuccess: (savedTodo) => {
    queryClient.setQueryData(['todos'], old =>
      old?.map(t => (t.id === savedTodo.id ? savedTodo : t)),
    )
  },
  // 方式 B：失效重拉（二选一或并用）
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['todos'] })
  },
})
```

## 四、相关方法总览

| 方法 | 行为 |
|---|---|
| `invalidateQueries` | 标过期 + 可选重拉（最常用） |
| `refetchQueries` | 强制重拉（不标过期，直接请求） |
| `resetQueries` | 重置到初始（清 data、恢复 pending） |
| `removeQueries` | 移除缓存数据 |
| `cancelQueries` | 取消进行中请求 |
| `setQueryData` | 手动写缓存 |
| `fetchQuery` | 命中缓存直接返回，否则请求并写入 |

## 五、失效时机最佳实践

- **增删改**后 → 失效对应列表 key。
- **切条件/筛选** → 失效该筛选前缀。
- 需要「省请求」时 → mutation 成功用 `setQueryData` 直接写。
- 需要「绝对一致」时 → `onSettled` 里 `invalidateQueries`。
