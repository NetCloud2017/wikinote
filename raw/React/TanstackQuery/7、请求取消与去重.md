# 请求取消与去重

> **版本基线**：`@tanstack/react-query` **v5.104.x**。
> 官方文档：<https://tanstack.com/query/v5/docs/framework/react/guides/query-cancellation> · <https://tanstack.com/query/v5/docs/framework/react/guides/queries>

## 一、去重（Deduplication）

**多个组件/多次渲染请求同一数据 → 合并为一次真实请求。**

TanStack Query 默认对**相同 key** 的查询做去重：

| 场景 | 表现 |
|---|---|
| 同一组件内 `useQuery` 重复渲染 | 只发一次请求 |
| 多个组件用相同 key | 共享同一份缓存与请求 |
| 并行 5 个组件请求 `['todos']` | 真实请求 **1 次** |
| 请求进行中又挂载新实例 | 复用进行中的请求 |

> 去重由「**缓存中的进行中 Promise**」保证：key 相同的查询在请求未结束时，新实例直接 await 同一个 Promise，而非重新发起。

## 二、请求取消（Query Cancellation）

核心机制：TanStack Query 会向 queryFn 传入 **`AbortSignal`**（在 `QueryFunctionContext.signal` 上），用于**在需要时中断进行中的请求**。

### 什么时候会被取消

- 查询被移除/失效/组件卸载且无其他订阅者时
- 新的请求发起并满足取消条件
- 手动 `queryClient.cancelQueries()`

### 传递 signal 给 fetch（推荐）

```ts
const query = useQuery({
  queryKey: ['todos'],
  queryFn: async ({ signal }) => {
    const res = await fetch('/api/todos', { signal }) // fetch 原生支持 abort
    if (!res.ok) throw new Error('请求失败')
    return res.json()
  },
})
```

> `fetch` 原生支持 `signal`。把 `signal` 一路传下去即可实现真正的中止。

### 手动取消

```ts
// 取消所有匹配 key 的查询（它们会被标记为取消）
await queryClient.cancelQueries({ queryKey: ['todos'] })
```

### 取消后的错误处理

被取消的请求通常会抛 `AbortError`。TanStack Query 会把「因取消而失败」与「真实错误」区分：

```ts
useQuery({
  queryKey: ['todos'],
  queryFn: async ({ signal }) => {
    try {
      return await fetchData(signal)
    } catch (err) {
      // 被取消的错误不该当业务错误处理
      if (signal.aborted) throw new DOMException('Aborted', 'AbortError')
      throw err
    }
  },
})
```

### `cancelRefetch`（v5 新增于 refetch）

`refetch` 可控制是否先取消当前请求：

```ts
refetch({ cancelRefetch: true }) // 默认 true：先取消进行中的再重拉
refetch({ cancelRefetch: false }) // 不取消，等旧的跑完
```

## 三、与「手动更新缓存」配合

取消后常配合 `setQueryData` 做**乐观回滚**或**本地修正**（详见第 10 篇）：

```ts
const queryClient = useQueryClient()

async function onDelete(id: string) {
  await queryClient.cancelQueries({ queryKey: ['todo', id] })
  // 取消后手动设置，避免竞态
  queryClient.setQueryData(['todo', id], undefined)
}
```

## 四、要点小结

| 关注点 | 结论 |
|---|---|
| 是否默认去重 | 是（相同 key 合并请求） |
| 取消靠什么 | `AbortSignal`（queryFn context 提供） |
| fetch 怎么取消 | `fetch(url, { signal })` |
| 取消算不算错误 | 不算业务错误，按 AbortError 处理 |
| 手动取消 API | `queryClient.cancelQueries({ queryKey })` |
| v5 refetch 取消开关 | `cancelRefetch` |
