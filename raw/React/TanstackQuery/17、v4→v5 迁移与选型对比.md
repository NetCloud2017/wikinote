# v4→v5 迁移与选型对比

> **版本基线**：`@tanstack/react-query` **v5.104.x**。
> 官方文档：<https://tanstack.com/query/v5/docs/framework/react/guides/migrating-to-v5>

## 一、v4 → v5 迁移要点

### 1. 统一为对象式 API（最重要）

| v4 | v5 |
|---|---|
| `useQuery(key, fn, options)` | `useQuery({ queryKey, queryFn, ...options })` |
| `useInfiniteQuery(key, fn, options)` | `useInfiniteQuery({ queryKey, queryFn, ...options })` |
| `useMutation(fn, options)` | `useMutation({ mutationFn, ...options })` |
| `useQueryClient` / `useIsFetching` 等 | 仍存在，签名调整 |

> v5 **只保留对象式单签名**，取消 v4 的多参数重载。类型推导也更严格。

### 2. 状态命名变化

| v4 | v5 |
|---|---|
| `isLoading` | 拆为 `isPending` + `isFetching`（`isInitialLoading = isPending && isFetching`） |
| `keepPreviousData` | 并入 `placeholderData: keepPreviousData` |
| `dataUpdatedAt` 等时间戳 | 保留 |

### 3. 无限查询

| v4 | v5 |
|---|---|
| `getNextPageParam` / `getPreviousPageParam` | 保留 |
| （无） | **`initialPageParam` 必填** |
| `refetchPage` | 新增 **`maxPages`** 替代，限制缓存页数 |

### 4. 其他重要改动

- `cacheTime` → 更名为 **`gcTime`**。
- 成功数据 **不能为 `undefined`**（resolve `undefined` 视为失败）。
- `useMutationState` 需配 `filters` 使用。
- DevTools 独立包 `@tanstack/react-query-devtools`。
- 新增 `useSuspenseQuery` / `useSuspenseInfiniteQuery` / `useSuspenseQueries` / `usePrefetchQuery`。
- `staleTime: 'static'` 新增（更严格的永不重拉）。
- 最低要求 React 18。

## 二、TanStack Query vs 传统状态库（选型）

| 维度 | TanStack Query | Redux / Zustand / Pinia |
|---|---|---|
| 定位 | **服务端状态**（异步缓存） | **客户端状态**（通用） |
| 缓存 | 内置（去重/失效/GC/后台刷新） | 需自己实现 |
| 请求生命周期 | 内置 status/fetchStatus | 需手写 loading/error |
| 去重 | 相同 key 合并请求 | 无 |
| 服务端同步 | staleTime/轮询/重连刷新 | 无 |
| 是否该用它管理本地状态 | **不适合**（无本地状态概念） | 适合 |
| 最佳组合 | **两者共存**：TSQ 管服务端，Zustand 管客户端 |

> 结论：**不是二选一，而是分工**。服务端数据交给 TanStack Query；弹窗/表单/主题等客户端状态交给 Zustand 等。用 TanStack Query 管本地 UI 状态是常见误用。

## 三、TanStack Query vs SWR / Apollo 等

| 库 | 特点 |
|---|---|
| **TanStack Query** | 框架无关、API 全、v5 强类型、社区最大 |
| SWR | 更轻、聚焦请求缓存，配置少 |
| Apollo Client | GraphQL 专用，含缓存归一化 |
| RTK Query | 与 Redux 深度绑定 |

> 主流选型参考（用户偏好「用得多、社区活跃」）：TanStack Query 在 **React 数据请求库中下载量/星标领先**，且生态独立于任何状态库，是通用推荐。

## 四、总结

| 问题 | 答案 |
|---|---|
| 现在该用哪个版本 | **v5**（当前最新 5.104.x，无 v6） |
| 老项目 v4 咋办 | 按上表迁移，主要改对象式 API + 命名 |
| 服务端状态该谁管 | TanStack Query |
| 客户端状态该谁管 | Zustand 等 |
| 能替代状态库吗 | 不能，二者互补 |
