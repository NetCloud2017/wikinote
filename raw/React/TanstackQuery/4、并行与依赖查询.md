# 并行与依赖查询

> **版本基线**：`@tanstack/react-query` **v5.104.x**。
> 官方文档：<https://tanstack.com/query/v5/docs/framework/react/guides/parallel-queries> · <https://tanstack.com/query/v5/docs/framework/react/guides/dependent-queries>

## 一、并行查询（Parallel Queries）

「并行」指**同时发起**多个互不依赖的请求，让它们并发执行。

### 方式 1：静态并行——多个 useQuery

各自独立的 `useQuery` 天然并行，互不阻塞：

```ts
const users = useQuery({ queryKey: ['users'], queryFn: fetchUsers })
const projects = useQuery({ queryKey: ['projects'], queryFn: fetchProjects })
// 两者同时触发、并发请求
```

### 方式 2：`useQueries` —— 动态 / 批量并行

适合**数量不固定**、或来自一个数组的情况，可统一 loading：

```ts
import { useQueries } from '@tanstack/react-query'

const ids = [1, 2, 3, 4]

const userQueries = useQueries({
  queries: ids.map(id => ({
    queryKey: ['user', id],
    queryFn: () => fetchUserById(id),
  })),
})

// userQueries: 与 ids 同长度的查询结果数组
const allLoaded = userQueries.every(q => q.isSuccess)
```

> `useQueries` 的 `queries` 数组**内部用相同结构**，且会自动合并每个查询的状态。v5 支持 `combine` 合并结果。

### combine：把结果合并成一个对象

```ts
const userQueries = useQueries({
  queries: ids.map(id => ({ queryKey: ['user', id], queryFn: () => fetchUserById(id) })),
  combine: results => ({
    data: results.map(r => r.data).filter(Boolean),
    isLoading: results.some(r => r.isPending),
  }),
})
```

## 二、依赖查询（Dependent Queries）

后一个请求**依赖**前一个请求返回的数据才能发起。

### 场景 A：同一组件内的链式依赖

关键点：后一个查询在 `enabled: false` 前**不执行**，拿到前置数据后再开启。

```ts
function UserProjects({ userId }: { userId: string }) {
  // 第一步：拿用户
  const user = useQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
  })

  const userIdReal = user.data?.id

  // 第二步：只有拿到 user 才查项目
  const projects = useQuery({
    queryKey: ['projects', userIdReal],
    queryFn: () => fetchProjectsByUser(userIdReal!),
    enabled: !!userIdReal, // 关键：数据未就绪时禁用
  })

  return projects.data?.map(p => <li key={p.id}>{p.name}</li>)
}
```

### 场景 B：**跨组件**共享依赖结果

更推荐：让「前置查询」在**父级/缓存**里先完成，子组件直接复用缓存：

```ts
// 子组件仍用同一 key，若缓存已有则秒回，实现"依赖"
const { data: user } = useQuery({ queryKey: ['user', id], queryFn: () => fetchUser(id) })
const { data: projects } = useQuery({
  queryKey: ['projects', user?.id],
  queryFn: () => fetchProjectsByUser(user!.id),
  enabled: !!user?.id,
})
```

> 好处：前置数据在缓存中就绪后，`enabled` 自动放行，且不会重复请求。

## 三、`enabled` 选项详解

`enabled` 是依赖查询/按需查询的开关，常用：

| 用法 | 效果 |
|---|---|
| `enabled: !!userId` | 数据就绪前不请求 |
| `enabled: false` | **永远不自动请求**（手动 `refetch` 可触发） |
| `enabled: isEnabled` | 表单/条件驱动 |

> v5 里 `enabled: false` 时查询不会自动跑，但可通过 `refetch()` 手动触发；返回的 `status` 为 `pending`。

## 四、三者对比

| 方式 | 触发 | 依赖 | 推荐场景 |
|---|---|---|---|
| 多个 `useQuery` | 并行 | 无 | 互不依赖的静态查询 |
| `useQueries` | 并行（可 combine） | 无 | 数量动态 / 数组批量 |
| `enabled` 依赖链 | 串行 | 有 | 后置请求依赖前置结果 |
