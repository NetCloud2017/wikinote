## 项目开发步骤

1. 了解项目结构和现有代码；
2. 了解需求，并输出修改计划；
3. 以最小修改原则，不要修改需求之外的代码和逻辑；进行需求开发；
4. 代码 diff , review 和运行测试代码和 eslint 检测；观察页面修改情况；
5. 没错误就commit;

## 上下文管理

对话就是上下文，但不完全等于上下文，因为codex的理解空间有限（大约 200K 左右）。随着对话的增加，它不会把所有的对话都记着。

1. 同一个任务,同一一个bug保留上下文；
2. 任务完成，换一个任务或者上下文混乱等清空上下文；
3. 长任务中途，要总结和管理上下文；

codex  resuem --last 回顾当前进度，再告我我下一步准备做什么？ 而不是恢复旧聊天就开始干活。 

长任务需要主动压缩上下文，关键提示词： 总结任务目标、已完成内容、关键决策、剩余问题;
主动总结让重要信息更容易在压缩时保留。

图片改bug流程： 
1. 截图告诉 codex 这是一张什么图；
2. 指出图中哪些地方有哪些问题；
3. 说出修改的目标；

若是下次出现同样的问题，也需要重新执行一次以上的流程吗？ 其实不用。我们只要创建套这样的规则，让codex 每次修改都遵守这套规则就可以了。创建这套规则我们需要在根目录创建一个 AGENTS.md 文件。 AGENTS.md 时项目级长期规则， codex进入项目时会读取，并在后续任务中持续参考。

## AGENTS.md 三层结构

1. 项目命令 
```
npm run build
npm start
npm run test
```

2. 代码规范
```
优先使用 TypeScript
保持现有组件结构
不做无关重构
```

3. 工作规则
```
改前说计划
改后跑验证
测试失败先分析
```

AGENTS.md 
```markdown
##项目命令
- 启动: npm run dev
- 测试： npm run test
- 构建： npm run build
## 工作规则
1. 修改前先说明计划， 最小改动
2. 修改后测试或构建
3. 总结修改 + 验证结果
## 代码规范
- 优先使用 TypeScript, 复用已有 class 
```

## 使用 codex 搭建 Agent

这里主要分为四个部分，分别为： 模型、工具、记忆和它的执行流程，对应到具体的能力上就是: 
MCP: 连接外部工具
Skills: 沉淀可复用流程
Sub agents: 多个 agent 去执行测试或审查等工作
Hooks: 自动执行规则，在关键节点插入校验。  

**Skills** 
Skills 适合存储一套可以重复执行的流程， AGENTS 适合存规则。常见用途： 日报、代码审查、发布说明、安全检查；

例如：我要审查代码改动时，codex 按照固定流程检查潜在的bug， 测试缺口， 安全风险和可维护性问题。 请生成 SKILL.md 文件。内容用中文， 先不要写入文件， 先展示给我确认。

**SubAgent** 
提示词： 
	⌈请使用 Subagent 并行审查当前 git diff ， 派出三个 Agent: 
	1. 安全审查 Agent ，检查权限、输入校验、敏感信息和潜在安全风险
	2. 测试审查Agent， 检查这次改动是否缺少测试， 现有测试是否覆盖了关键路径
	3. 可维护性审查Agent， 检查代码结构、重复逻辑、命名和长期维护风险
	请等待三个 Agent 都完成后再汇总结果， 最后按严重程度排序， 并给出文件位置和修改建议， 暂时不要修改文件。

一般情况不用 subagent ，因为他会并行修改代码，容易产生冲突。
