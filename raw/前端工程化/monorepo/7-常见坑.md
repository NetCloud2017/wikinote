# 7. 常见坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **构建顺序错** | `ui` 还没 build，`web` 就开始 build，找不到 `@acme/ui/dist` | `turbo.json` 里写 `dependsOn: ["^build"]`，让 Turbo 自动拓扑排序 |
| **循环依赖** | `utils` import 了 `ui`，`ui` import 了 `utils`，TS/打包器报循环引用警告 | 拆包：把共享类型抽到第三个包 `@acme/types`；或把 `utils` 里被 `ui` 用到的部分下沉到 `@acme/shared` |
| **幻影依赖（phantom deps）** | 代码 `import _ from 'lodash'` 但本包 `package.json` 没声明 `lodash`，靠 hoisting 侥幸跑通；换个机器/CI 直接炸 | pnpm 默认严格模式会直接报错；每个包显式声明自己用到的依赖，不要跨包借用 |
| **重复打包 react** | `ui` 和 `web` 都装了 react，bundle 里两份 react，hooks 报错 Invalid Hook Call | `react` 放到 `ui` 的 `peerDependencies`，让使用方（app）提供唯一一份 react |
| **缓存失效** | 改了环境变量 `API_URL`，但 Turbo 还命中旧缓存，跑出来的还是旧值 | turbo.json 里用 `env` / `globalEnv` 声明依赖的环境变量；`inputs` 里加上 `.env` 文件 |
| **仓库太大** | `git clone` 慢、CI checkout 慢、IDE 卡 | 用 `git-filter-repo` 清理历史中的大文件；binary 资源走 Git LFS；考虑把不活跃的包拆到独立仓库 |
| **changeset 漏提交** | PR 改了代码但忘了跑 `pnpm changeset`，合并后版本号没升 | CI 加检查：PR 改了 `packages/*` 但 `.changeset/` 没新文件就 fail；或用 changeset bot 评论提醒 |
| **内部包改了但下游没重新 build** | 改了 `utils`，`web` 里跑的还是旧 utils 产物 | Turbo 的 `^build` 会自动处理；本地开发用 `turbo run dev --filter=@acme/web...` 让 utils watch 模式跟着 build |
| **pnpm install 在 CI 慢** | 每次 CI 都全量装 | 用 `pnpm/action-setup` + `actions/setup-node` 的 pnpm store 缓存；CI 上用 `--frozen-lockfile` |
| **ESM/CJS 混用** | 库发出去，CJS 项目 `require` 报错，ESM 项目 `import` 报错 | package.json 同时配 `main`（CJS）、`module`（ESM）、`exports`（条件导出）；用 tsup / tsdown 一次打出双格式 |
| **端口冲突** | `turbo run dev` 并行起多个 app，端口撞了 | 每个 app 的 dev script 用 `PORT=3001 next dev -p $PORT` 自动分配；或用 Turbo 的 `persistent` 任务串行起 |

pnpm dlx madge --circular packages/

# 输出任何 circular 路径都要拆

## 幻影依赖检查

pnpm 默认严格模式已经会报错。如果老项目迁移要临时放开：

```ini
# .npmrc
shamefully-hoist=true    # 临时，迁完删掉
```

## peerDependencies 正确姿势

```jsonc
// packages/ui/package.json
{
  "peerDependencies": {
    "react": ">=18.0.0",
    "react-dom": ">=18.0.0"
  },
  "devDependencies": {
    "react": "^18.3.0",          // 开发时自己装一份跑测试
    "@types/react": "^18.3.0"
  }
}
```

这样：
- 发出去的 `ui` 不会把 react 打包进去
- app 装 `@acme/ui` 时自动 peer 提示安装 react
- `ui` 自己跑测试时用 devDependencies 里的 react
