# 3. 任务编排（Turborepo / Nx）

## 为什么需要任务编排

包管理器只解决"装依赖"和"软链内部包"，不解决"先 build 谁"的问题。

假设：
- `@acme/ui` 依赖 `@acme/utils`
- `@acme/web` 依赖 `@acme/ui`

你执行 `pnpm -r run build`，包管理器并行跑所有包的 build——结果 `ui` 还没 build 完，`web` 就开始 build 了，找不到 `@acme/ui/dist`，直接报错。

**任务编排工具**解决两件事：
1. **拓扑排序**：按依赖关系决定 build 顺序（先 utils → 再 ui → 最后 web）
2. **缓存**：没改动的包直接复用上次产物，跳过执行

## 主流工具对比

| 工具 | 出品方 | 语言 | 核心卖点 | 适用规模 |
|---|---|---|---|---|
| **Turborepo** | Vercel | Rust | 速度极快、配置简单、远程缓存 | 中型 |
| **Nx** | Nrwl | TypeScript | 依赖图可视化、code generator、affected 精细、企业级 | 大型 |
| Lerna | 社区（已被 Nx 收购） | JS | 老牌，现基本并入 Nx | 老项目 |
| Rush | 微软 | TypeScript | 超大型 monorepo 的完整工具链 | 巨型 |
| Bazel | Google | Starlark | 远程执行 + 缓存，极致性能 | 巨型 |

## Turborepo 核心概念

### task graph（任务依赖图）

```jsonc
// turbo.json
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"]     // ^ 表示"先把上游依赖包的 build 跑完"
    }
  }
}
```

`^build` 的意思：build 我之前，先把所有我依赖的包的 build 跑完。这样就自动处理了 utils → ui → web 的顺序。

### 缓存

```jsonc
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]        // 声明哪些目录是产物，命中缓存就复用
    }
  }
}
```

Turbo 根据以下输入算 hash：
- 包的源码文件
- `inputs` 里声明的额外文件（如 tailwind.config.ts）
- 依赖包的版本
- `env` / `globalEnv` 里声明的环境变量

hash 命中 → 直接把 `outputs` 还原回来，跳过执行。

### affected（增量构建）

```bash
# 只跑相对于 main 分支有改动的包，以及依赖它们的下游
turbo run build --filter="...[origin/main]"
```

`...[origin/main]` 的意思是：对比 `origin/main`，找出改动的包，再把它们的下游都带上。

### 并行执行

Turbo 自动并行跑没有依赖关系的任务。比如 `apps/web` 和 `apps/admin` 可以同时 build。

## Nx 核心概念

Nx 比 Turborepo 更重，但功能更多：

- **Nx Graph**：可视化依赖图，`pnpm nx graph` 起一个网页看包与包、任务与任务的关系
- **Code Generators**：`pnpm nx g @nx/react:lib ui` 自动生成包骨架
- **Nx Cloud**：托管远程缓存 + 分布式任务执行（CI 上多个机器分片跑）
- **微调 affected**：`pnpm nx affected:build --base=main`
- **Inferred Tasks**：自动识别项目里的 package.json script、Vite/Webpack 配置，不用手写 pipeline

### Turborepo vs Nx 怎么选

| 场景 | 选择 |
|---|---|
| 中小团队、想快速上手、配置少 | Turborepo |
| 大团队、需要 code generator、依赖图可视化、CI 分布式 | Nx |
| 老项目用 Lerna | 迁到 Nx（官方路径） |

## 最小 turbo.json

```jsonc
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"]
    },
    "dev": {
      "cache": false,
      "persistent": true
    },
    "lint": {},
    "test": {
      "dependsOn": ["build"]
    }
  }
}
```
