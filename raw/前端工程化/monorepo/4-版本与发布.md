# 4. 版本与发布（Changesets）

## SemVer 语义化版本

版本号格式：`MAJOR.MINOR.PATCH`

- **PATCH**（1.0.x）：bug 修复，向后兼容
- **MINOR**（1.x.0）：新功能，向后兼容
- **MAJOR**（x.0.0）：Breaking change，不兼容旧版

## 为什么需要 Changesets

Multirepo 时代发版流程手动：改代码 → 改 `package.json` 版本号 → 写 CHANGELOG → npm publish。

Monorepo 下有 N 个包，手动发版会疯：
- 哪个包改了？该升 PATCH 还是 MINOR？
- CHANGELOG 谁写？
- 内部包互相依赖，版本号怎么联动？

**Changesets** 把发版流程变成：
1. 改代码时顺手跑 `pnpm changeset`，选包、选 bump 类型、写一句话说明
2. 这个 changeset 文件提交到 git
3. CI 或手动跑 `changeset version`，自动把 changeset 应用到 `package.json` 版本号 + 生成 CHANGELOG
4. `changeset publish` 发 npm

## 工作流

```bash
# 1. 改完代码，生成 changeset
pnpm changeset
# 交互式选择：哪些包改了？patch/minor/major？一句话说明？

# 2. 把 .changeset/xxx.md 提交到 git
git add .changeset/
git commit -m "feat(ui): add Button component"

# 3. PR 合并到 main 后，CI 跑：
pnpm changeset version     # 升版本号 + 写 CHANGELOG.md
pnpm turbo run build       # 先构建
pnpm changeset publish     # 发 npm
```

## `.changeset/config.json`

```jsonc
{
  "$schema": "https://unpkg.com/@changesets/config@3.0.0/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "fixed": [],                          // 哪些包锁定版本一起发
  "linked": [],
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": ["@acme/web"]              // 不发 npm 的包（应用类）
}
```

## fixed vs independent

| 策略 | 说明 | 适用 |
|---|---|---|
| **independent**（默认，`fixed: []`） | 每个包独立版本，改哪个发哪个 | 大多数 monorepo |
| **fixed / locked** | 配置在 `fixed: [["@acme/ui", "@acme/utils"]]`，这一组包版本号绑死一起升 | 真正同步演进的套件（如 Next.js 全家桶） |

## dist-tag

npm 发版默认打到 `latest` tag。预发布版本用其他 tag：

```bash
# 进入 pre 模式（beta）
pnpm changeset pre enter beta

# 正常发版，会发到 beta tag 而不是 latest
pnpm changeset publish
# 用户安装：npm install @acme/ui@beta

# 验证完毕，退出 pre 模式，正式版发 latest
pnpm changeset pre exit
pnpm changeset publish
```

常用 tag：
- `latest`：稳定版（默认）
- `beta`：公测版
- `next`：下一个大版本的预览
- `canary`：每次 CI 自动发的临时版

## CHANGELOG 自动生成

`changeset version` 会自动在每个包根目录写 `CHANGELOG.md`：

```markdown
# @acme/ui

## 0.2.0

### Minor Changes

- add Button component
- fix Input focus style
```

## 哪些包不该发 npm

配置里的 `ignore` 字段：
- `apps/web`、`apps/admin` 这种应用类，不发 npm
- `packages/tsconfig`、`packages/eslint-config` 这种内部配置包，可选发也可不发
- `packages/ui`、`packages/utils` 这种真正被外部用的库，必须发

## 替代方案

- **Lerna**：老牌，`lerna version` + `lerna publish`，现基本被 Changesets 取代
- ** changesets + pnpm publish**：也可以不用 changesets CLI，自己写脚本，但不推荐
- **语义化发布（semantic-release）**：基于 commit message 自动决定版本号，适合单包；monorepo 下不如 changesets 直观
