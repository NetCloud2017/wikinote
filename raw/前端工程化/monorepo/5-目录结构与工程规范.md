# 5. 目录结构与工程规范

## 标准目录约定

```
my-monorepo/
├── apps/                       # 可部署的应用（不发 npm）
│   ├── web/                    # @acme/web（Next.js）
│   └── admin/                  # @acme/admin
├── packages/                   # 可复用的库（发 npm）
│   ├── ui/                     # @acme/ui（组件库）
│   ├── utils/                  # @acme/utils（工具函数）
│   ├── hooks/                  # @acme/hooks（React hooks）
│   └── tsconfig/               # @acme/tsconfig（共享 tsconfig，内部用）
├── tools/                      # 内部脚本/工具（不发 npm）
│   └── scripts/
├── .changeset/
├── .github/
│   └── workflows/
├── pnpm-workspace.yaml
├── turbo.json
└── package.json
```

### apps/ vs packages/ vs tools/

| 目录 | 放什么 | 是否发 npm | 例子 |
|---|---|---|---|
| `apps/` | 可独立部署的应用 | 否 | web、admin、docs、storybook |
| `packages/` | 可复用的库 | 是（除内部配置包） | ui、utils、hooks、tsconfig |
| `tools/` | 内部脚本、CI 工具 | 否 | 发版脚本、自动生成器 |

## 命名规范

- 所有包统一 scope：`@acme/xxx`
- 应用类：`@acme/web`、`@acme/admin`
- 库类：`@acme/ui`、`@acme/utils`、`@acme/hooks`
- 配置类：`@acme/tsconfig`、`@acme/eslint-config`

## TypeScript project references

包多了之后，`tsc` 全量编译慢。用 project references 让 TS 只 build 改动的包：

```jsonc
// packages/utils/tsconfig.json
{
  "extends": "@acme/tsconfig/base.json",
  "compilerOptions": {
    "outDir": "dist",
    "composite": true              // 关键：声明这个包可被引用
  },
  "include": ["src"]
}
```

```jsonc
// packages/ui/tsconfig.json
{
  "extends": "@acme/tsconfig/base.json",
  "compilerOptions": {
    "outDir": "dist",
    "composite": true
  },
  "references": [                  // 关键：声明依赖的包
    { "path": "../utils" }
  ],
  "include": ["src"]
}
```

根目录 `tsc -b` 会按引用拓扑顺序编译。

## 共享配置

把 ESLint / Prettier / tsconfig 做成内部包，业务包直接 extends：

```
packages/
├── tsconfig/
│   ├── base.json
│   ├── nextjs.json
│   ├── node.json
│   └── package.json            # name: "@acme/tsconfig"
└── eslint-config/
    ├── index.js
    ├── react.js
    └── package.json            # name: "@acme/eslint-config"
```

业务包里：

```jsonc
// packages/ui/package.json
{
  "devDependencies": {
    "@acme/tsconfig": "workspace:*",
    "@acme/eslint-config": "workspace:*"
  }
}
```

```jsonc
// packages/ui/tsconfig.json
{ "extends": "@acme/tsconfig/base.json" }
```

## 何时该拆包、何时不该拆

**该拆**：
- 两个模块被多个 app 共用 → 拆成 `packages/`
- 一个模块有独立发版需求 → 拆成 `packages/`
- 一个模块有独立测试需求 → 拆成 `packages/`

**不该拆**：
- 只在一个 app 里用 → 放 app 内部，别拆
- 拆了之后包之间要来回改（高频耦合）→ 先合着，等稳定再拆
- 为了"架构好看"硬拆 → 过度设计
